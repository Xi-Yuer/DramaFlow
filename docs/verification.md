# 验证方式与限制

## 检查层次

- contracts/typecheck：平台协议与消费者保持一致。
- context 单元测试：上下文隔离、来源预算、原始消息保留、建议操作白名单。
- workflow 契约测试：分支跳过、并行汇合、Output 后继、人工恢复、取消和批量。
- plugins HTTP 契约：官方 SDK 真实序列化、错误归一化、能力校验、无隐式重试。
- API 集成：真实 PostgreSQL/pgvector、Redis、登录会话、权限、发布与运行闭环。
- 浏览器：编辑、保存、配置插件、人工确认、会话建议及失败空状态。

## 本地运行

先按 README 初始化数据库、迁移和管理员，再执行 `pnpm check`。单个包可以通过 `pnpm --filter @dramaflow/workflow test` 等命令验证。集成测试如果需要独立服务或环境会在输出中明确说明。

## 真实模型

仓库不包含真实供应商密钥。HTTP 契约测试只证明适配器行为，不证明某个账号、模型和区域当前可用。首次使用时在界面创建真实连接，进行小规模文本与图片生成，核对供应商记录、平台 operation、资产版本和上下文清单。

视频供应商、成片合成、任意循环、批量单项历史替换、长期记忆和 RAG 属于后续能力。未配置的生成能力显示不可用，不会以固定图片或字符串代替生成。

实际执行过的验证与发现的限制会记录在实施完成报告中；未运行或缺少凭证的部分不得标为通过。

## RustFS 切换验证（2026-10-16）

- `pnpm test:storage`：4 项通过，真实 RustFS，验证二进制、MIME、私有访问、历史 local 读取与缺少凭证时失败。
- `pnpm test:integration`：4 项通过，真实 PostgreSQL、Redis、API、worker 与 RustFS；模型供应商使用本地 HTTP 契约服务，不调用付费模型。
- API 类型检查、静态检查与构建通过；集成入口执行了整个 workspace 构建，通过。
- 单独测试对象在 RustFS 容器强制重建后 SHA-256 一致，随后清理。
- 新环境配置生成和幂等初始化检查通过，不改写已有凭证。
- 本机 ARM64 的 1.0.1 镜像解包约 239 MiB；一次空闲采样约 61 MiB 内存。这不是负载测试结果，也不是服务器最低配置承诺。

RustFS 单节点无数据冗余；大视频分片上传、流式读取和历史本地资产的批量搬迁未在这一轮实现。

# 前端设计要求与样式提示词

## 使用约定

本文件定义后续界面的视觉与交互方向。实施前阅读下方提示词，按用户当轮指定的页面或组件应用，不据此自动恢复业务功能或重做整站。

当前使用 Ant Design、Next.js Registry 和 TanStack Query，主题入口为 `apps/web/src/app/theme.ts`。登录页和账户中心已应用石墨灰与青色主题，通用表单、密码输入、选择器、页签、菜单、提示和弹窗复用组件库。定制样式集中在页面布局与少量装饰；后续按具体模块继续遵守下方提示词。

节点界面读取纯 JSON NodeTypeManifest，配置由 config 字段数组描述，控件提示只在 config[].ui；输入提示位于 ui.inputs。metadata.category 固定八类，图标与 component 使用受控映射，不加载 Zod、execute 或模型实例。number 的范围来自配置字段，不在 slider UI 重复保存。DataType 使用 primitive / named / array / object / union / any，端口 key 对应 Handle.id；声明不代表已有配置表单、模型或资产选择服务，边界见 [Manifest 实施说明](node-type-implementation.md)。

react-flow-adapter.ts 将 Workflow.edges 中的 Data Edge 无损映射为 React Flow Edge，保留边 ID、两端节点与 Handle；Handle.id 必须等于 Manifest 的端口 key。显式连线先对照精确版本 Manifest 检查端口、共享静态类型兼容及目标单连接，再创建 Data Edge，并移除被显式替换的目标静态 Binding；数组输入也不自动接收多条边。断连和重连核对完整旧边快照；selected、dragging、measured 不持久化。GenericWorkflowNode 按精确类型版本 Manifest 自动生成 Handle，缺失显示不可用；画布查询目录、注册 renderer 并接入 Data Edge 事件。当前生产目录为空，没有节点添加与 Workflow 持久化，项目保存仍只有名称、视口及 revision。相关边界见 [Node 模型](node-model.md)。

## 可直接用于后续实施的样式提示词

为 DramaFlow 设计一个面向 AI 漫剧及多媒体创作的专业创作空间。整体气质应当安静、精致、现代、有沉浸感，像供创作者长期使用的画布与内容编辑工具。让作品、画面、提示词和正在进行的创作成为视觉中心，界面框架保持轻盈。风格关键词：深色中性、石墨质感、柔和圆角、精细层级、少量电光青、浮动操作、内容优先。

### 1. 配色与层次

- 以近黑、炭灰和石墨灰构成主工作区，不使用大面积藏蓝或企业蓝。可将页面、面板、输入区分别控制在接近 `#090909`、`#18191d`、`#242426` 的中性深色层次，具体数值通过统一主题令牌调整。
- 主要文字为柔和的近白色，次要文字为有足够对比度的中灰；辅助信息降低视觉权重，但不能灰到难以阅读。
- 青色或偏青的冷色用于关键交互、焦点和少量选中状态，避免把所有按钮、图标和边框都染成强调色。中性白色主按钮也可用于节点局部生成操作。
- 成功、警告、失败采用独立的语义色，配合图标与文字说明。节点能力的区分色只用于小面积标识，节点本体保持中性。
- 如后续增加浅色模式，延续相同的信息层级和组件形态，采用雾灰底与白色面板；不能只做机械反色。

### 2. 空间与页面骨架

- 按创作任务组织空间。侧边导航紧凑、低对比度、可收起；顶部只放当前对象、上下文切换和必要操作，控制高度，不制造厚重的导航框架。
- 创作区尽量占据主要面积。参数、素材、对话等辅助信息按任务需要放在侧面板、抽屉或局部浮层中，避免让所有面板永久挤占画布。
- 项目和素材以封面、缩略图及简洁标题形成可浏览的内容集合；用图片比例和间距建立节奏，减少重复嵌套卡片。
- 保持明确对齐和适度留白。普通浏览区舒展，节点内操作紧凑；信息密度随任务变化，不把每个区域都做成同样大小的卡片。

### 3. 面板、圆角与材质

- 面板使用细微明度差、低透明度细边框和柔和阴影分层。深色边框可参考白色 5%—12% 的透明度，悬停或聚焦后适度增强。
- 常规面板圆角约 12—16px，大型浮层约 16—20px；小控件与缩略图可用 6—10px，轻量工具条和标签可用胶囊形。按组件角色统一，不任意混用。
- 仅浮动工具条、弹出面板等局部位置使用适量半透明与背景模糊；输入和正文区域优先保证可读性。
- 选中效果以清晰细描边、轻微亮度变化为主；必要时加入很弱的青色光晕。不要给所有节点和卡片常驻发光。

### 4. 画布与节点

- 画布采用安静的深色底和低对比度点阵或网格。连线、端口和选中状态要清楚，但不能压过生成内容。
- 节点像可直接操作的内容容器：简洁标题、较大的文本或媒体展示区、收敛的局部操作。媒体预览保持比例，优先呈现真实内容。
- 将模型选择、参数、引用素材和生成按钮组织在就近的紧凑操作区；可使用节点下方浮动面板、胶囊工具条或按需展开的配置区。
- 悬停、选中、连接、运行、等待人工确认和失败状态具有明确差异。关键操作不能只能依赖鼠标悬停发现，键盘聚焦或触屏也应可达。
- 工具条、缩放控制、上下文菜单和预览浮层保持同一种材质、边框与圆角体系，避免画布与外围界面出现两套视觉语言。

### 5. 排版、图标与控件

- 使用清晰、克制的无衬线字体；中文优先适配苹方、思源黑体等，英文可使用 Geist 或气质相近的字体。正文以 13—14px 为主，辅助标签约 11—12px，标题适度放大，用字重和间距区分层级。
- 图标使用同一套简洁线性图标，保持一致的尺寸、线宽和按钮内对齐。独立图标按钮提供可访问名称和必要的提示。
- 输入框、模型选择器、标签、菜单和按钮共享主题令牌。次级操作使用中性、透明或轻填充样式，让主操作自然突出。
- 表单聚焦、禁用、校验与加载状态保持完整；弹窗支持焦点管理、键盘操作和合理滚动，避免只追求外观。

### 6. 动效与科技感

- 科技感来自细节：轻微的悬停提亮、柔和浮起、工具条出现、侧栏收放、标签切换和生成过程反馈。常规反馈约 150—250ms，布局展开可适度延长，动作平滑而克制。
- 项目封面可使用轻量的层叠、景深或展开反馈，但不要让每张卡片持续运动。
- 光束、边缘微光和局部渐变只在确有作用的生成反馈、选中或入口区域使用；尊重减少动态效果的系统偏好。
- 避免大面积霓虹、持续闪烁、夸张粒子、过强玻璃效果和背景装饰遮挡内容。

### 7. 明确避免的方向

- 不采用阿里系后台、传统管理系统或通用 Admin Dashboard 的视觉模板。
- 不使用固定的“深蓝宽侧栏＋白色顶栏＋统计卡片行＋数据表格”作为全站默认布局。真实业务需要的表格、列表和统计可以使用，但不让它们定义整个创作产品的外观。
- 不用巨大营销标题、装饰性欢迎横幅、虚构指标或无意义的图表填充空间。
- 不照搬其他产品的品牌、文案、插画、素材或业务结构；本提示词只定义视觉和交互语言。

### 8. 组件与实现方式

- 优先安装和复用成熟组件、无样式交互原语及专业画布能力。使用统一的主题令牌控制颜色、圆角、间距、阴影和动效，避免逐页面堆叠样式。
- 根据目标视觉评估现有组件库能否自然实现；必要时按模块评估 shadcn/ui、Radix UI、Base UI、成熟的可调整面板或动效组件。它们是候选工具，不要求全部安装，也不据此自动迁移组件库。
- 避免为同一职责引入多套组件库。不要手写已有成熟方案能够处理的弹窗、菜单、焦点陷阱和键盘交互；自定义代码集中在创作场景特有的布局与节点展示。
- 本提示词不授权新增业务。每次只实现用户当轮明确指定的范围，完成真实状态、错误反馈和必要的响应式检查，不用模拟业务数据制造完成感。

# 一次工作流如何运行

## 定义不是运行状态

`WorkflowDefinition` 保存节点实例、执行连线和数据绑定。节点类型规定配置及输入输出，实例只保存用户选择。`NodeExecutor` 接收解析后的输入并返回自己的输出；`RuntimeHost` 保存结果、生成任务和审核任务。

例子：输入 → 剧本生成 → 人工确认 → 图片生成 → 结果收集。生成节点必须明确配置 `model = { pluginId, pluginVersion, connectionId, modelId }`。剧本与分镜是文本节点的业务预设，不复制供应商逻辑。

数据绑定可引用字面量、工作流输入或某节点输出的字段。执行连线则决定哪个节点需要执行。二者的依赖并集必须无环；仅仅引用跨分支数据不能把未选中的分支唤醒。

## 发布与启动

1. 保存草稿时检查 revision，防止覆盖其他编辑。
2. 发布时校验节点、配置、端口、绑定、联合依赖和插件引用，保存不可变版本。
3. 启动接口接受幂等键，创建 run 并入唤醒队列。
4. worker 加载冻结版本和已有结果，用 PostgresSaver 恢复或调用图。
5. 宿主持久化节点尝试和事件；界面经 SSE 接收进度，刷新后可以查询恢复。

## 条件和汇合

每个节点只注册一组上游依赖屏障。条件节点记录选中的出口；不改变 LangGraph 的静态拓扑。未选中的包装节点返回 `skipped`，不校验业务必需输入、不调用生成接口，也不创建人工任务。

这样不等长并行分支能完成汇合，互斥分支也不会永远等不到未运行节点。活跃节点如果需要一个已跳过分支的必需值，返回结构化错误；可选绑定允许缺失。`merge` 的 selected 模式要求恰好一个候选可用；多个候选同时可用会明确报错，collect 模式按绑定顺序收集可用值。

结果收集是普通节点：接受多个命名输入，保留原类型，登记本组结果并允许后继继续执行。运行完成等待全部静态叶子结束，而不是遇到第一个 Output 就结束。失败运行仍可查询已完成的结果集。

## 人工确认与恢复

审核节点独立于生成节点。`interrupt` 暂停后，人工任务记录待处理输入。用户批准、编辑或拒绝后，服务端检查权限、状态和幂等键，再恢复对应中断。

LangGraph 恢复可能重新进入节点函数，不能把生成 API 放在审核 interrupt 前而期待它只运行一次。重复确认也不能提交第二次生成任务。

## 操作账本与不确定结果

外部调用不能承诺 exactly-once。宿主在调用前记录 operation，保存稳定操作键；成功后保存输出与供应商任务标识。重启恢复复用同一记录，用户主动重新生成使用新记录。

若网络中断或 5xx 使受理状态无法确认，操作进入 `outcome_unknown`。此时不能自动再发一个可能收费的请求；先查供应商任务或由用户检查后显式重生成。参考 SDK 关闭自动重试。

## 批量与重生成

批量节点冻结有序条目，使用 LangGraph `Send` 调用单一能力，按条目标识合并并按原顺序输出。空数组直接输出空数组。每项有独立操作键，恢复时复用已完成项。并行数有上限，不能以数组长度无限并发。

“重新生成”由节点动作声明决定。用户可只生成目标的新版本，或明确从目标继续下游；未受影响的上游结果复用，受影响下游标记失效。批量主动重生成以整个批次为单位，首期不提供任意历史条目的局部替换。

# 上下文构建与双会话

## 两种范围

节点会话只围绕当前节点：配置、明确绑定的上游输出、相邻执行路径、用户选中的素材和该节点的历史消息。工作流全局会话获得当前图的结构摘要、数据绑定及用户选中的运行状态。它不会自动获得所有节点对话全文或全部产物。

图片、视频节点的旁侧对话仍然需要支持 `chat` 的模型连接；视频生成接口不能被当作对话接口调用。

## ContextBuilder 的输入与输出

`buildContext` 接收会话范围、工作流 revision/发布版本、历史消息、当前请求、可选摘要、明确选择的运行和素材版本、模型上下文上限及预算策略，返回 `ContextBundle`。

其中 `messages` 是本次实际发给模型的内容；`manifest` 记录来源、版本、是否纳入、裁剪原因、输入预算和长度估算。它不包含密钥。预览与真正调用共用构建函数，避免界面显示一套、服务端发送另一套。

生成节点也调用该服务，但使用 `purpose: 'generation'`；对话默认 `purpose: 'conversation'`。前者执行明确的生成需求，后者只能分析和建议，不能共用相互冲突的系统指令。

## 预算与记忆

先保留系统约束、当前请求及明确选择的工程上下文，再预留输出和安全余量。历史只选择近期完整轮次；工具调用与结果必须配对。明确选择的素材超过预算时返回原因，不静默丢弃关键设定。

首期按中英文字符保守估算 token，界面标明 approximate；估算不是实际计费用量。模型或兼容连接可配置上下文上限，供应商返回的 usage 另行保存。未知用量不能显示为零。

原始消息保持完整。摘要记录所覆盖的消息及派生版本，可以追溯回原文。摘要不意味着删除历史，也不是长期记忆或向量检索。

## 建议不等于执行

模型可以产生白名单领域操作组成的建议：更新节点配置、重命名、增删节点、修改执行边及数据绑定。建议绑定基础 revision。用户查看内容并确认后，服务端重新校验工作空间权限、版本和图，再保存新草稿。

同一建议重复确认不会重复应用；其他用户已编辑造成的冲突必须显示。应用建议不会启动模型生成或工作流运行。生成按钮与继续执行是独立动作。

## 以后如何扩展

后续加入素材 RAG 时，在 PostgreSQL 启用的 pgvector 上增加素材片段、嵌入维度与模型版本、权限过滤和检索来源记录。检索结果仍通过 ContextBuilder 装配，不能让检索器绕过工作空间权限。当前不维护空的 embedding 表或假检索接口。

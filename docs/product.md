# 产品定位与方向

## Current Product

DramaFlow 是团队自部署的可视化 Workflow 工具，当前 AI 生产能力以文本生成为主。用户需要理解节点、输入输出、版本和运行；产品没有把完整视频或漫剧生产流程封装成普通用户任务。

登录使用团队分配的账号。首页展示项目列表；每个项目对应一张画布和一个逻辑 Workflow，项目主要承担所有者隔离、画布信息和执行数据归属。模型供应商、凭证与模型配置属于账号，在该用户的项目之间共用。

典型操作路径：

```text
登录 → 新建项目 → 配置节点、模型和输入输出 → 保存草稿
→ 发布版本 → 选择版本并运行 → 审核或查看结果 → 修改草稿并再次发布
```

当前普通 Picker 提供文本生成、子流程和人工审批。条件分支属于 advanced 条目，Iteration 属于 internal 条目，没有高级模式切换界面；已有节点可按其 Manifest 编辑。Catalog 暴露与 Runtime 执行准入是不同边界。

画布支持显式数据与控制连接、输入输出边界、模板变量、嵌套图编辑、设计与运行 Inspector。运行工作区提供已发布版本选择、输入表单、状态与结果、文本审核、取消、运行历史和执行树。查看运行版本不会覆盖正在编辑的草稿。

## 当前产品边界

- Workflow Outputs 与节点执行详情承载生成结果。inline 文本和 JSON 可显示；引用结果只显示身份，collection 尚不能展开。
- 人工审核支持文本预览、反馈和通过 / 拒绝，不直接编辑正文，也不自动建立返工流程。
- 没有独立素材库、上传素材产品链路、候选结果管理、作品管理或最终作品导出。
- 没有图片 / TTS / 视频生产插件、Timeline / Composition、全局 Agent 或业务模板入口。
- 没有剧集、角色、分镜等持久内容对象；项目名称和创作文案不代表这些业务能力存在。
- 当前为项目所有者隔离，没有项目成员协作模型、公开 SaaS 或商业计费。

## Direction / Blueprint

长期方向是 Workflow-driven AI content production platform，优先服务视频创作与漫剧，也可覆盖其他内容生产场景。这是产品方向，不是已交付能力。

| 层次                | 职责                                                         |
| ------------------- | ------------------------------------------------------------ |
| Product Layer       | 内容生产对象、素材与结果管理、业务模板、审核修改和交付体验   |
| Authoring Layer     | 通用 Canvas、Catalog、Inspector、嵌套导航与运行工作区        |
| Workflow Foundation | 中立的定义、编译、绑定、执行身份、checkpoint、取消与运行观测 |

产品层通过 Node、Plugin、Contract 和已有图组合表达生产意图，不让 Runtime 理解特定业务。内容对象、结果采用与交付流程可以逐步产品化；这里不预设具体业务 Schema，也不把更多基础 primitive 视为必经前提。

建议或 Agent 能力若进入产品，应只提出建议；应用配置、生成和继续执行需要明确操作，并重新校验权限与版本。上下文只引入明确选择的数据，不自动把完整 State 或对话送入模型。

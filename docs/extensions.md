# 新增节点与模型插件

## 先判断扩展属于哪一层

“生成剧本”和“生成商品描述”通常复用文本生成节点，只增加提示词/配置预设。“调用另一家图片厂商”增加模型插件。“执行一种新的确定性数据变换”才需要新增节点类型。

节点定义负责用户能力和数据契约，插件负责供应商协议。不要为每个厂商复制一套文本/图片节点，也不要把厂商参数写进图编译器。

## 新增模型插件

1. 在 `packages/plugins` 中添加独立供应商模块，定义稳定插件 ID 与版本。
2. 声明 capabilities、连接 Schema、分能力的参数 Schema、模型描述及实际支持的特性。兼容 Chat Completions 不代表兼容图片、工具或视频。
3. 实现 `ModelProvider` 的相应方法。接收的是已构建消息/需求、显式参数和本次凭证，不能读取整个工作流状态。
4. 关闭 SDK 隐式重试，区分确定拒绝与受理状态不明；错误不能回显请求头、原始 SDK 对象或密钥。
5. 添加到受信任服务端注册表和浏览器安全 manifest 列表。界面启用和连接配置不等于安装任意上传代码。
6. 用本地 HTTP 服务测试实际请求、响应、参数差异、错误与重复调用；真实联调使用自己的服务配置。

`models` 可以为空，表示用户必须明确填写厂商模型标识，不代表平台默认选择某个模型。参数面板遵循 manifest，不支持的特性应提前说明。

## 视频协议

视频提供 `submitVideo`、`pollVideo`、`cancelVideo`，声明供应商任务 ID、状态、结果和错误。提交操作与轮询分开持久化。恢复时先查询旧任务，不能一恢复就再次提交。

只有插件实际声明视频能力并实现对应协议，视频节点才可执行。取消能力由供应商支持情况决定，平台不能把本地取消宣称为供应商已停止计费。

## 新增节点类型

1. 扩展平台节点类型和目录中的定义，声明版本、输入输出、配置 Schema、控制出口及用户动作。
2. 在运行时注册执行行为或分派到受控执行器；只返回本节点结果，不操作下游、不直接访问数据库。
3. 前端继续复用目录、Schema 表单、端口和节点外壳；特殊预览采用独立组件。
4. 补充激活/跳过、类型校验、失败和恢复测试，并更新文档。

核心控制节点与模型节点统一经过运行包装器，因此新增能力不会绕过权限、事件和持久化。

## 你可以先参与的任务

从“增加一个剧本润色预设”开始：复用 text 类型，填写提示词，保留模型手选。然后运行“输入 → 润色 → 审核 → 收集结果”，检查配置怎样变成绑定输入、插件请求和运行产物。这个任务可以理解全链路，又不必同时修改执行引擎。
